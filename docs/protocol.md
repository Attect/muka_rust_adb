# 协议笔记

本项目以 AOSP `packages/modules/adb/docs/dev/protocol.md` 和 `services.md` 为准。

CLI 输出按 AOSP 区分两类错误：本地参数、usage、未知命令以及 forward/reverse/disconnect 的 server 结果继续使用可执行文件名前缀；`get-state`、`get-serialno`、`get-devpath`、`get-transport-id` 这组 host 查询收到 smart-socket `FAIL` 时使用 `error: <message>`，与 AOSP `adb_connect_command` 一致。

安装命令的参数优先级按 AOSP 保留：`install-multi-package` 会在连接或选择设备前解析 trailing APK/APEX；因此非法包类型或缺少安装文件时，即使当前存在多设备，也先返回 `need APK or APEX files on command line` 等本地错误。`install` 与 `install-multiple` 继续保留官方的设备选择优先级。

## smart-socket

host client 与 adb server 的请求格式：

```text
<4 位十六进制长度><ASCII service>
```

响应状态：

```text
OKAY
FAIL<4 位十六进制长度><错误文本>
```

返回字符串的服务会在 `OKAY` 后继续发送一段 protocol string。例如 `host:version`：

```text
client: 000Chost:version
server: OKAY00040029
```

其中 `0029` 是官方 server version 41 的十六进制形式。

## apacket

transport 层消息头固定 24 字节，所有字段为 little-endian：

```text
command
arg0
arg1
data_length
data_check
magic = command ^ 0xffffffff
```

当前官方协议版本为 `0x01000001`，该版本允许跳过 payload checksum，发送端可将 `data_check` 写为 0。为了兼容旧版本，本项目仍实现了按字节求和的 checksum。

## 当前兼容范围

- 已实现 smart-socket 字符串读写、状态读写和 apacket 编解码。
- host client 的 server socket 解析已按官方优先级实现：命令行 `-L` 与 `-H/-P` 互斥；指定 `-L/-H/-P` 时忽略环境变量；否则优先使用 `ADB_SERVER_SOCKET`，再使用 `ANDROID_ADB_SERVER_ADDRESS`/`ANDROID_ADB_SERVER_PORT`。默认 client 连接地址为 `127.0.0.1:5037`，自动启动时原样保留 socket spec；`tcp:0` 可用于动态监听，`tcp:HOST` 按 AOSP 使用默认端口 5555，显式 hostname 会通过系统地址解析后依次尝试连接。server listener 按 AOSP 将 `tcp:localhost:PORT` 绑定到 IPv4 loopback，确保后续 `-P PORT` 客户端连接同一实例，不会因 IPv4/IPv6 地址族分裂误启动第二个 server；Unix 的显式 `[::1]` 仍保留 IPv6。Windows server smart-socket 支持 `tcp:`；Unix 额外支持 filesystem namespace 的 `local:`/`localfilesystem:` 和仅监听的 `acceptfd:`，Linux 还支持 `localabstract:` 与 `vsock:`。filesystem server 启动时按 AOSP 清除残留节点，退出后保留 socket 节点供下次启动对账。
- 全局参数错误边界按 AOSP 对齐：`-P`、`-H`、`-L`、`-s`、`-t`、`--one-device`、`--reply-fd` 缺参返回 `<option> requires an argument`；顶层错误打印使用当前可执行文件名作为前缀，避免固定 `error:` 包装，可打印 CLI/usage/server 错误按官方失败码退出 1；`--exit-on-write-error` 会按官方作为无参数全局选项消费；`-sSERIAL` 和 `-tID` 只有第三个字符是数字时才作为内联参数，否则返回缺参错误；`-L` 不支持 `-Ltcp:...` 内联形式，未识别的短横线 token 会退出全局解析并作为普通命令落到 `unknown command ...`。`help`/`--help`/`/?` 和 `version`/`--version` 虽不解析或连接实际 server socket，仍会先按 AOSP 校验 `-L` 与 `-H/-P` 互斥、`-P`/`ANDROID_ADB_SERVER_PORT` 范围及 `--one-device` 使用范围；单独的未知 `-L SOCKET` 仍可被这些纯本地命令忽略。全局帮助不接受 `-h`；`-h` 与裸 `--` 一样不是帮助别名或全局分隔符，应落到 `unknown command ...`。全局 modifier 消费完后若没有实际命令，会按 AOSP 打印帮助并以失败码退出。
- `help`/`--help`/`/?` 的版本头使用本项目版本、当前可执行路径和 host OS；从 `global options:` 开始的帮助正文按本机 AOSP `commandline.cpp` 逐字对齐，包含 networking/file transfer/shell/install/debugging/security/scripting/USB 分区、环境变量和官方在线文档链接。非 Windows host 按 AOSP 条件额外显示 `--local-agent`，Windows 不显示；三个帮助别名由官方二进制差分测试覆盖。
- 默认 transport 选择已支持 `ANDROID_SERIAL`：仅当命令行没有 `-s/-d/-e/-t` 时，非空 `ANDROID_SERIAL` 会作为默认 serial；显式选择器会覆盖该环境变量。
- `server`/`nodaemon`/`fork-server` 已按 AOSP 作为命令前置 modifier 解析：`adb server` 走后台启动，`adb server nodaemon` 和 `adb nodaemon server` 走前台 server；自动启动统一用 `-L SOCKET` 拉起 `fork-server server --reply-fd FD`，不再把 socket 降级为 `-H/-P`。启动参数会保留 `tcp:PORT` 与显式 `tcp:HOST:PORT` 的差别：只有未显式 host 的前者在配合 `-a` 时绑定 `0.0.0.0`，显式 host 仍按原地址绑定；`-a` 与 `--one-device` 均会传给后台子进程。父子进程分别使用 ACK、stdout、stderr 匿名管道，子进程 bind 或初始化失败时会把诊断转发给启动它的 client；成功路径在 bind、初始 emulator/USB 扫描完成并把 daemon stdout/stderr 切换到空设备后，向 reply fd 写官方启动 ACK `OK\n`。Linux TCP server 会在初始化后把 `/proc/self/exe` 写入 `.android/adb.<port>`；较旧 client 连接到本机更高版本 server 时，会先用该 marker 指向的独立 `adb` 程序保留原 argv/env 执行 re-exec，并用 `adb (re-execed)` guard 防止循环，marker 缺失或 exec 失败才回退到 kill/restart。非 TCP socket 不创建或读取该 marker。缺少 `--reply-fd` 时返回 AOSP 的 `reply fd for adb server to client communication not specified.`，`--reply-fd` 缺参返回 `--reply-fd requires an argument`，`--reply-fd` 为非整数或 `<=2` 时返回 `invalid reply fd "<value>"`。`--one-device SERIAL|USB` 已按官方限制为只能配合 server 启动类命令使用，包括 `start-server` 和这些 server modifier 组合。本项目 server 在 TCP/emulator/USB transport 注册前会按 serial 过滤，USB 设备还可匹配本项目无 serial 时使用的 `usb:<bus>:<addr>:<vid>:<pid>:<if>` fallback 标识。
- 最小 server 已能通过 `host:connect:<host[:port]>` 建立 TCP/local transport 初始握手；TCP、emulator 和 USB 连接会先以可关闭的 `offline` pending transport 注册，收到 `A_AUTH TOKEN` 后原位更新为 `authorizing`，握手成功后复用同一实例更新为 banner 状态，失败或显式断开则移除占位并打断底层 TCP/USB I/O。`host:devices[-l]` 和 tracker 因此可以观察 `offline`、`authorizing`、`device` 或 `unauthorized` 状态；server 启动和后台周期线程会按 AOSP emulator scanner 规则扫描本机 adb 端口 `5555,5557,...,5585`，注册 serial 为相邻 console 端口形式 `emulator-5554`、`emulator-5556` 等，支持 `ADB_EMU=0` 禁用和 `ADB_LOCAL_TRANSPORT_MAX_PORT` 调整最大端口。
- 已实现双向设备服务桥接：server 发送 `A_OPEN` 时，service payload 按 AOSP 兼容历史 adbd 保留尾随 NUL；等待远端 `A_OKAY` 后向 smart client 返回 `OKAY`，远端 `A_WRTE` payload 直接写给 client，并回 `A_OKAY`。设备为 reverse 主动发来 `A_OPEN` 时，host 按 AOSP 在每个 transport 上维护 `reverse:forward/killforward/killforward-all` allowlist，只连接已登记的 local 目标；Windows 支持 `tcp:<port>`/`tcp:<host>:<port>`，Unix 额外支持 filesystem namespace 的 `local:`/`localfilesystem:`，Linux 额外支持 `localabstract:` 与 `vsock:<CID>:<PORT>`。host `localreserved:` 不可用，`acceptfd:` 只允许监听而不可连接；未登记或连接失败的目标返回 `A_CLSE(0, remote-id)`。host 仅在 `ADB_BURST_MODE=1` 时把 `delayed_ack` 加入 CNXN feature；双方协商成功后 `A_OPEN.arg1` 携带 32 MiB 初始 credit，host 回 `A_OKAY` 时携带 4 字节 little-endian 已写入字节数。
- server 监听 socket 可保持 nonblocking，但 accept 出来的 smart-socket client 必须恢复 blocking 模式；Windows 上继承 nonblocking 时，长度前缀读取会以 10035 `WouldBlock` 提前失败并导致客户端看到 10053。accept loop 会识别 legacy `host-*:forward/killforward` 首请求，并在对应全局规则变更完成后再接受下一连接，使“不读取响应就关闭、立即另连查询”的旧客户端仍获得 AOSP event loop 顺序；tracker 等长连接不会进入该门控。设备端 `A_WRTE` 写回某个已关闭 smart client 失败时，只能对该 stream 回 `A_CLSE` 并移除 stream，不能关闭整个 transport。
- 当前桥接已经支持同一 TCP transport 上的多个 active stream，远端包由后台读线程按 local-id 分发。
- 已实现 `A_AUTH TOKEN` 签名：默认读取或生成 `~/.android/adbkey`，`keygen FILE` 可显式生成 `FILE` 和 `FILE.pub`，`pubkey FILE` 会从私钥重新计算并打印 Android 公钥，缺参或多参的 CLI 错误文案与 AOSP 一致为 `keygen/pubkey requires an argument`；签名按官方 `RSA_sign(NID_sha1, token)` 语义把 20 字节 TOKEN 当作 SHA1 digest 做 PKCS#1 v1.5 prehash 签名；默认公钥按 Android `RSAPublicKey` 结构编码为 base64 文本，发送时以 NUL 结尾 payload 下发 `ADB_AUTH_RSAPUBLICKEY`。
- 已实现 `ADB_VENDOR_KEYS` 扫描：文件直接加载，目录只加载一层 `*.adb_key`。
- 已实现 shell v2 客户端解帧：packet header 为 1 字节 id 加 4 字节 little-endian 长度；`STDIN=0` 写远端 stdin，`STDOUT=1` 写本机 stdout，`STDERR=2` 写本机 stderr，`EXIT=3` 第一个 payload 字节作为进程退出码，`CLOSE_STDIN=4` 关闭远端 stdin，`WINDOW_SIZE_CHANGE=5` 发送形如 `24x80,0x0\0` 的 ASCII 窗口尺寸。非交互 `shell COMMAND` 使用 `shell,v2,raw:`，持续把 host stdin 编码为 `STDIN` packet，并在 EOF 后发送 `CLOSE_STDIN`；交互 `shell` 会按 `-T/-t/-tt` 选择 `raw/pty`，在 pty 模式下启用本机 raw mode，发送初始窗口尺寸，并周期性检测本机终端尺寸变化后发送 `WINDOW_SIZE_CHANGE`。Windows raw mode 按 AOSP 保存并精确恢复原始 stdin console mode，清除 processed/line/echo input 并启用 window input；raw stdin 使用 `ReadConsoleInputW` 把方向键、Home/End、Insert/Delete、F1--F20、数字键盘、Shift/Ctrl/Alt 修饰和 AltGr 转成 AOSP `_console_read` 的类 xterm 序列，UTF-16 输入转为 UTF-8，并兼容 ConPTY 把非 BMP surrogate 放在 key-up record 的形态；普通 key-up 仍被忽略，避免重复字符。stdin 和窗口尺寸变化共用写入锁，避免多个后台写入源交错破坏 shell v2 packet；raw stdin 的行首 `<escape>.`（默认 `~.`）按 AOSP 立即打印断开提示、关闭 transport 并以 0 退出，不误发 `CLOSE_STDIN`，其他 escape 组合会原样回放。交互输出不长期占用 stderr 锁，避免 stdin 线程打印断开提示前自锁；legacy 交互 shell 复用相同 escape 状态机，普通 stdin EOF 不做 half-close。shell 选项边界保留 AOSP 输出形态：`-e` 缺参和未知短选项由 shell 子命令直接打印 `adb shell: ...` 并静默退出，`-e` 非单字节取值返回 `-e requires a single-character argument or 'none'`，`-x` 最终未分配 pty 时直接打印 `error: -x only supports allocating a pty`。
- fastdeploy 的 `apply` 在 shell v2 路径中把 packet id、little-endian payload 长度和 payload 组装为单次写入的完整 frame，避免 smart-socket bridge 按写入边界拆包；读取 `EXIT` 非零状态会返回 host 可识别错误并回退到普通 streamed/push install。API 28 和 API 34 真机已验证更新后的设备 APK SHA-256 与本地 APK 一致。
- 已实现 `exec-in`/`exec-out`：缺参入口按 AOSP 返回 `usage: adb exec-in command` 或 `usage: adb exec-out command`；按 AOSP CLI 规则拼接 `exec:<command>`，第一个命令参数直接附加，后续参数使用 shell 参数转义；`exec-out` 只把设备端 stdout 复制到本机 stdout，`exec-in` 只把本机 stdin 写入设备端 service。终端型 `exec-in` 按 AOSP `copy_to_file`/`stdin_raw_init` 启用 raw mode，并在 Windows 复用 `ReadConsoleInputW` 转换层；管道或文件 stdin 保持原始字节流。
- 已实现基础 `abb` CLI：先检查设备 feature `abb`，缺失时按 AOSP 返回 `abb is not supported by the device`，不走中文 `Unsupported` 包装；再打开 `abb:<arg0>\0<arg1>...` service；参数分隔符与 AOSP `ABB_ARG_DELIMETER` 一致为 NUL，输出和退出码按 shell v2 协议解帧。
- 已实现基础 `sync:` 客户端：请求头为 4 字节 little-endian ID 加 4 字节 little-endian 长度，路径最大 1024 字节，数据块最大 64 KiB；旧设备使用 v1 `STAT/LIST/SEND/RECV`，新设备按 AOSP `CanUseFeature` 交集语义选择 v2 `LST2/LIS2/SND2/RCV2` 和 dry-run 能力。v2 `sync_stat_v2`/`sync_dent_v2` 会完整解析 `dev/ino/mode/nlink/uid/gid/size/atime/mtime/ctime` 并保留在内部条目上，v1 条目没有这些扩展字段。`adb ls` 使用 `LIST/DENT` 或 `LIS2/DNT2` 并按官方 `mode size mtime name` 十六进制四列输出；`push` 发送 v2 dry-run，`-q` 抑制汇总输出，`ADB_COMPRESSION` 可作为默认压缩算法。显式 `-z brotli|lz4|zstd` 在 legacy 设备上按官方忽略并回退 v1 uncompressed，在 v2 设备上直接发送相应 flag；只有 `-z any` 按 feature 以 zstd/lz4/brotli/none 优先级选择。Brotli、LZ4 frame 和 Zstd 压缩流都会继续按 `DATA` 帧分块传输。
- `sync:` 连接关闭按 AOSP `SyncConnection` 析构语义 best-effort 发送 `QUIT`，显式 `quit()` 幂等；server/transport stub 测试按字节流累计 sync frame，不假设一个 `A_WRTE` 对应一个完整 sync 消息。

- 已实现 USB transport 基础路径：通过 vendored libusb 枚举设备配置，按 AOSP `is_adb_interface` 规则识别普通 ADB gadget `(0xff,0x42,0x01)` 和 DbC `(0xdc,0x02,0x01)` interface，并要求存在 bulk IN/OUT 端点；枚举时记录 `usb:<bus>-<port.path>` 拓扑地址、libusb 协商速率和按 USB descriptor 推导且不低于协商值的最大 Mbps；打开时设置 kernel driver auto detach、claim interface、clear halt，ADB packet 按官方 libusb 路径拆成 24 字节 header bulk transfer 和 payload bulk transfer，payload 长度正好对齐 bulk-out max packet size 时发送 ZLP；libusb bulk-in reader 使用短 timeout 轮询显式 close 标志，timeout 本身不会当作断线，`Transport::close()` 会调用底层 `AdbConnection::close_connection()` 以释放 libusb interface 或 shutdown TCP。Windows 和 Unix 均使用同一 Rust/libusb USB backend，Windows x64 `adb.exe` 静态包含 libusb 和 MSVC CRT，不依赖 `AdbWinApi.dll`/`libusb-1.0.dll`/`VCRUNTIME140.dll`；Windows 32 位不在支持范围内。server 启动和后台周期线程都会尝试注册 USB transport；transport reader 失效后会标记 closed，底层任一 packet 写失败也会关闭整个 transport，server 随后清理 registry 并唤醒 `track-devices`/`wait-for`。Windows server 按 AOSP 创建隐藏顶层窗口和独立消息泵来监听 `WM_POWERBROADCAST/PBT_APMRESUMEAUTOMATIC`，并在窗口就绪后才完成 server 初始化；恢复后关闭所有旧 USB transport、移除关联 forward、保留显式 attach registry 并立即重新枚举。周期枚举还会移除已经离场且没有读线程的 detached libusb 占位。显式 `detach`/`attach` 保留原 serial/transport id；descriptor serial 在重新枚举时偶发缺失也不会生成 fallback serial 双条目，attach 失败会回滚 attached registry，重新 claim 前会等待旧 bulk-in reader clone 越过 250ms poll timeout 并释放 handle。USB transport 复用 TCP transport 的 CNXN/AUTH/OPEN/OKAY/WRTE/CLSE 状态机；不同 Windows 驱动和原生 libusb hotplug callback 仍需继续验证。

- 已实现 `host:disconnect:<target>` 官方响应语义：空目标只断开 TCP/local transport，返回 `disconnected everything`，不会移除 USB transport；指定目标先按现有 transport serial/devpath/product/model/device 匹配，再按 TCP 地址归一化到默认 5555 端口，成功返回 `disconnected <target>`，找不到返回 smart-socket `FAIL no such device '<serial>'`，`tcp:`/`udp:` 前缀按 AOSP local target 兼容规则忽略。
- 已实现基础 `server-status`：server 返回 `host:server-status` 的 `AdbServerStatus` 二进制 protobuf，CLI 解码为 text protobuf 输出，并与 AOSP 一致不检查尾随参数；当前字段覆盖 usb/mdns backend 及 forced 状态、版本、构建、可执行路径、实际日志路径、AOSP 形态 OS 字符串、`ADB_TRACE`、`ADB_BURST_MODE`、mdns enabled、`keystore_path` 和 `known_hosts_path`；forced 字段遵循 proto3 非 optional bool 的默认值省略规则，并兼容新版官方 `LIBADBMDNS` enum。`ADB_TRACE` 支持 AOSP 的 `1`/`all` 和 `adb,sockets,packets,rwx,usb,sync,sysdeps,transport,jdwp,services,auth,fdevent,shell,incremental,mdns,mdns-stack` 标签，逗号或空格均可分隔；未知标签按官方输出 `Unknown trace flag: <tag>`。`adb`、`1` 或 `all` 还会像官方一样在纯本地命令前记录客户端版本元信息和最终 server socket，其他单独标签不会误触发该启动诊断。后台 server 会把 stdout/stderr 追加到该日志路径。
- 已实现基础 `mdns check|services`：CLI 查询 `host:mdns:check/services`，缺参、未知子命令和多余参数的错误文案按 AOSP `commandline.cpp` 固定；校验顺序也与官方一致，裸 `mdns` 在本地报缺参且不启动 server，只要存在子命令 token 就先检查/启动 server，再校验未知子命令或多余参数。server 启动时按 `ADB_MDNS` 开关决定是否创建 `mdns-sd` 后端，并监听 `_adb._tcp.local.`、`_adb-tls-connect._tcp.local.`、`_adb-tls-pairing._tcp.local.`。`mdns check` 在后端启用时返回官方 Openscreen 文案 `mdns daemon version [Openscreen discovery 0.0.0]`，禁用时返回 `ERROR: mdns discovery disabled`；`mdns services` 从当前仍 active 的发现表输出官方三列 `instance service address:port`，仅输出 IPv4 地址以匹配 AOSP 文档。`host:connect:<name>` 会先按 AOSP `mdns_parse_instance_name` 解析 mDNS 实例名；未显式给 service 时优先 `_adb-tls-connect._tcp`、再回退 `_adb._tcp`，显式 `_adb-tls-pairing._tcp` 不会作为 connect 目标。TCP connect 收到 `A_STLS` 后会回包并升级 TLS 1.3，再在 TLS 内等待第二次 `A_CNXN` 和桥接普通 ADB packet。mDNS create/update 事件已接入自动连接：`ADB_MDNS_AUTO_CONNECT` 默认只允许 `adb-tls-connect`，secure connect 必须命中 `adb_known_hosts.pb`，`0` 禁用、`all` 允许 legacy adb 与 secure connect，并排除 emulator/pairing service；fresh server 状态在收到已知 secure-connect 实例时会排入同一自动连接队列，连接按实例去重，首次失败或自然断线后按 AOSP 250ms 初始等待、3 秒间隔、最多 20 次重试，endpoint 更新会用于下一次连接，显式 `disconnect` 会取消恢复。真实无线设备重启后的 mDNS 事件时序和跨平台网络恢复仍需硬件验证。
- 已实现 `adb pair HOST[:PORT] [PAIRING CODE]` 的官方 CLI 与协议流程：缺少 host 或参数过多时返回 `usage: adb pair HOST[:PORT] [PAIRING CODE]`；未给配对码时提示 `Enter pairing code: ` 并从 stdin 读取，空配对码返回 `No pairing code provided`；随后发送 `host:pair:<code>:<host>` 查询。server 按 AOSP `host_service_to_socket("pair:")` 规则用第一个冒号切分 password/host，解析 mDNS pairing 实例名或显式 `HOST:PORT`，使用现有 `adbkey` 生成临时自签证书并完成 TLS 1.3 双向证书握手，再把 `adb-label` 导出的 64 字节 key material 拼到配对码后执行 BoringSSL 兼容 SPAKE2；PeerInfo 使用 HKDF-SHA256 派生的 AES-128-GCM 密钥和固定 8192 字节结构交换，成功后把设备 GUID 追加到 `adb_known_hosts.pb`。错误配对码或连接中断返回官方 `Failed: Wrong password or connection was dropped.`。
- 已实现 `attach`/`detach` 的官方 CLI/service 入口：CLI 与 AOSP 一致不检查尾随参数，并先按当前 selector 执行 transport switch，再在同一 smart-socket 连接上发送裸 `host:attach` 或 `host:detach`。本项目已建模官方 `detached` 连接状态，设备列表使用文本 `detached`，protobuf tracker 使用状态值 `5`/`DETACHED`，wait-active 判定中视为非 active；对 detached/offline transport 打开普通 device service 时返回 AOSP 文案 `device offline (transport offline)`。server 已按 AOSP `LibUsbConnection::SupportsDetach` 边界实现 libusb USB transport 的 `detach` 生命周期和 `ADB_LIBUSB_START_DETACHED=1` 启动策略：未显式 attach 的 libusb 设备会注册 detached 占位，避免后台 USB 扫描直接 claim；周期枚举会按 serial/devpath 删除已经拔出的 detached 占位，但不会因一次枚举缺失误杀 active USB transport；`detach` 会关闭并释放当前 transport、移除关联 forward listener、从 attached registry 移除 serial，并留下 detached 占位；`attach` 会先写入 attached registry，再按 serial/devpath 重新枚举并复用原 transport id 重新 CNXN/AUTH。`Transport::close()` 会调用底层 `AdbConnection::close_connection()` 以打断后台 reader 并释放 USB claim。
- 已实现基础 `emu` console 命令：CLI 不经过 adbd service，而是按 AOSP `client/console.cpp` 逻辑解析唯一 `emulator-<console-port>` serial，直连 `127.0.0.1:<console-port>`；存在用户目录 `.emulator_console_auth_token` 时先发送 `auth <token>`，随后发送用户命令和 `quit`；无 console 子命令时不提前报 usage，仍只发送 `quit\n`；读取 console 输出并跳过初始 greeting 中前两个 `OK\r\n` 块。
- 已实现 `logcat`/`lolcat`/`longcat` 的官方 shell 包装路径：本机 `ANDROID_LOG_TAGS` 会被 POSIX 单引号转义后导出，`longcat` 自动追加 `-v long`，其余参数逐个转义后交给设备端 `logcat`。`bugreport` 参数多于一个时按 AOSP 返回 `usage: adb bugreport [[PATH] | [--stream]]`。
- 已实现 `reboot [TARGET]`、`reboot-bootloader`、`reboot-fastboot` 官方 service 映射：无目标打开 `reboot:`，普通目标打开 `reboot:<target>`，旧式 bootloader/fastboot 命令固定映射到 `reboot:bootloader`/`reboot:fastboot`；`sideload-auto-reboot` 按官方目标字符串透传。
- 已实现 `usb` 官方 service 映射：无附加参数打开 `usb:`，存在附加参数时按 AOSP 只取第一个参数拼到冒号后，例如 `usb reset ignored` 发送 `usb:reset`。
- 已实现 `root`/`unroot` 官方 service 映射：固定打开 `root:`/`unroot:` 并读取设备输出，附加参数不参与 service 构造。
- 已实现 `remount`、`disable-verity`、`enable-verity` 的基础兼容：当设备 feature 包含 `remount_shell` 时走无输入 shell 命令；否则回退旧式 `remount:`、`disable-verity:`、`enable-verity:` device service，旧式 service 按 AOSP 只把第一个附加参数拼到冒号后，例如 `remount -R extra` 发送 `remount:-R`。
- 已实现基础 `bugreport`：先用 shell v2 捕获 `bugreportz -v` 的 stdout/stderr；默认 zip 路径解析 `BEGIN:`、`PROGRESS:`、`OK:`、`FAIL:` 控制行，再用当前 `sync:` v1 pull 拉回主机；`--stream` 走 `bugreportz -s`，无 `bugreportz` 且无参数时回退纯文本 `bugreport`。`bugreportz -p` 进度输出在终端上按 AOSP LinePrinter 语义使用 `\r` 覆盖同一行，非终端仍按行输出。
- 已实现旧式 `backup`/`restore` service 包装：`backup` 抽取任意位置的 `-f FILE`，要求剩余参数包含包名或 `-all/-shared`，默认写入 `backup.ab`，打开 `backup:` 后把设备输出复制到本地文件；`restore` 缺参入口按 AOSP 返回 `usage: adb restore FILENAME [ARG]...`，打开本地文件，连接 `restore:` 后写入文件内容，再补两个 512 字节零块并等待设备端 EOF。两者都会保留官方 deprecated warning。
- 已实现基础 `sideload` 和 `rescue`：默认 sideload 连接 `sideload-host:<size>:65536`，设备端每次发送 8 字节十进制块号，主机按 64 KiB 块随机读取 OTA 包并回写；收到 `DONEDONE` 成功退出，收到 `FAILFAIL` 以非零退出。若新协议连接失败且文件不超过 2 GiB，会回退旧式 `sideload:<size>` 顺序发送。`rescue` 参数先在本地按 AOSP 校验，不会因非法参数拉起 server；`rescue getprop [PROP]` 打开 `rescue-getprop:` 或 `rescue-getprop:<prop>`，`rescue install OTAPACKAGE` 复用同一按块传输循环但服务名为 `rescue-install:<size>:65536`，失败不回退旧式 sideload；`rescue wipe userdata` 打开 `rescue-wipe:userdata:8` 并读取 8 字节 `DONEDONE/FAILFAIL` 结果。
- 已实现 Linux host 侧 `vsock:<port>` forward/server listener：server 使用 AF_VSOCK 绑定 `VMADDR_CID_ANY`，forward 的 `vsock:0` 会回显内核分配的端口；client 侧 `vsock:<CID>:<port>` 可连接既有 server，remote forward 的 `vsock:<CID>:<port>` 不在 host server 上解析，按官方规则作为设备端 service 透传。host 侧 `localreserved` 在 AOSP host socket spec 中标记为 unavailable，并返回官方 `attempted to listen on unavailable socket type`；全局 `-a` 会让 `forward tcp:<port>` 从 loopback 改为监听全部 IPv4 接口。
- 已实现 JDWP host 路径：`jdwp`/`track-jdwp` 按 AOSP 分别打开裸 `jdwp` 和 `track-jdwp` service，不能误写成需要 PID 的 `jdwp:<pid>`；`forward tcp:<port> jdwp:<pid>` 由 forward listener 透明桥接原始 JDWP 握手。transport 在设备 `A_OKAY` 后立即 `A_CLSE` 时仍会先完成 smart-socket `OKAY`，再以正常 EOF 结束，避免把短生命周期只读 service 误报为打开失败。设备端 JDWP 进程发现、调试权限和进程生命周期仍由目标设备的 `adbd`/ART 提供，本项目不重复实现设备端 agent。
- CLI 连接官方 server 时，可以利用官方 server 的真实设备 transport；连接本项目 server 时，只能使用当前 registry 中由 `host:connect` 登记的 TCP transport。
